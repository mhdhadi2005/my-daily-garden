# Domain docs

This is a single-context repo. Before exploring an area, read the
root `GLOSSARY.md` and relevant files in `docs/adr/` if they exist.
Use the glossary's terms in specs, issues, tests, and code.

Do not create empty domain docs during setup. `domain-modeling` creates
a glossary entry when a term is resolved and an ADR when a meaningful,
hard-to-reverse decision needs recording. Flag conflicts with existing
ADRs instead of silently replacing them.
